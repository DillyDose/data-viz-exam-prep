Munzner's Nested Model (2009)

4 ชั้น: Problem (โดเมนจริง) → Task/Data (นามธรรม) → Encoding/Interaction (การออกแบบ) → Algorithm (การ implement) — แต่ละชั้นมี "Threat" (จุดที่ผิดพลาดได้) กับ "Validate" (วิธีตรวจสอบ) ของตัวเอง ผิดพลาดชั้นบน (เช่น เข้าใจปัญหาผิด) ทำให้ทุกชั้นล่างพังตามแม้ implement ถูกทุกอย่าง.

Usability Testing: 3 ขั้น

  1. Define tasks — closed-ended (มีคำตอบชัด) เช่น "หาเดือนที่อัตราว่างงานสูงสุด"
  2. Find users — Convenience sampling (เพื่อน/ครอบครัว), Snowball sampling (เพื่อนของเพื่อน) — ไม่ต้อง random ก็ได้ แต่ห้าม re-test กลุ่มเดิมกับ prototype คนละเวอร์ชัน (learning effect)
  3. Test — บอกผู้ใช้ว่ากำลังทดสอบระบบไม่ใช่ทดสอบผู้ใช้ ให้พูดคิดออกเสียง (think aloud) ผู้ทดสอบต้องเงียบ ไม่ช่วย ไม่ชี้จุดผิด

Task Taxonomy

คู่ต่างกันอย่างไร
Validation vs EstimationValidation = มีเส้น/คำตอบให้ตัดสิน "ใช่/ไม่ใช่"; Estimation = ให้ผู้ใช้ตอบเองจากศูนย์
Reproduction vs FreeformReproduction = ทำตามภาพต้นแบบ; Freeform = ให้ออกแบบอิสระ

Nielsen's 5-User Rule

Jakob Nielsen (1993): usability test แค่ ~5 ผู้ใช้ ก็เจอปัญหา usability ส่วนใหญ่แล้ว (ผลตอบแทนลดลงเรื่อย ๆ หลังจากนั้น) — ไม่จำเป็นต้อง test ผู้ใช้เป็นร้อยคนถึงจะเริ่มแก้ไขได้.
