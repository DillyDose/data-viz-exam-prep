Interactive Visualization Cheat Sheet

Spatiotemporal Data: 2 วิธีเพิ่มมิติเวลา

วิธีข้อดีข้อเสีย
Small Multiplesเทียบทุกช่วงเวลาได้พร้อมกันในสายตาเดียว ไม่ต้องรอ/จำกินพื้นที่มาก (Space) เมื่อมีหลายช่วงเวลา
Animationกินพื้นที่น้อย (Space) เห็นการเปลี่ยนแปลงต่อเนื่องลื่นไหลต้องรอดู (Time) จำช่วงก่อนหน้าไม่ได้ถ้าพลาด

นี่คือตัวอย่างของ Space-Time Tradeoff ที่วนกลับมาซ้ำหลายรอบตลอดบทนี้: ยิ่งประหยัดพื้นที่ (space) มักต้องแลกด้วยเวลาที่ผู้ใช้ต้องเสีย (time) ไปเปิดดู/รอ และกลับกัน.

Interaction Techniques (Shneiderman-style taxonomy)

เทคนิคทำอะไร
Sortเรียงลำดับข้อมูลใหม่แบบโต้ตอบ
Details on Demandhover/select แล้วเผยรายละเอียดเพิ่ม (tooltip)
Dynamic Filteringปรับ slider/checkbox แล้วข้อมูลที่แสดงเปลี่ยนทันที
Pan & Zoomเลื่อนดู/ขยายเฉพาะส่วนที่สนใจ
Link & Brushเลือก (brush) ในภาพหนึ่ง ไฮไลต์จุดที่สัมพันธ์กันในอีกภาพ (link)
Overview + Detailมุมมองรวมกับมุมมองละเอียดแยกกันคนละพื้นที่ แต่ sync กัน
Focus + Contextบิด/ขยายเฉพาะจุดสนใจ โดยยังเห็นบริบทรอบข้าง (เช่น fisheye)
Direct Manipulationโต้ตอบกับตัว mark ในภาพโดยตรง ไม่ผ่าน widget แยก (proxy)

Objective ของ Interaction

ทุกเทคนิคข้างบนคือการเปลี่ยนพารามิเตอร์ของขั้นตอนใดขั้นตอนหนึ่งใน pipeline (Lecture 3): Data processing (เช่น filter), Visual mapping (เช่น เปลี่ยน encoding), หรือ Visual rendering (เช่น zoom/pan) — เพื่อช่วยให้ผู้ใช้หา insight ที่ static chart เดียวให้ไม่ได้.

Dashboard

"A dashboard is a visual display of the most important information needed to achieve one or more objectives, consolidated and arranged on a single screen so the information can be monitored at a glance" — หลักออกแบบสำคัญ: จัด Hierarchy (ข้อมูลสำคัญสุดควรเด่นสุด/อยู่บนสุด) และ Layout ที่ไม่บังคับให้ scroll เพื่อดูภาพรวม (ต้อง "glanceable" จริง ๆ)

Grand Tour

แปลง SPLOM (scatterplot matrix, Lecture 6) ให้เป็น animation — หมุน/ไล่ดูแต่ละคู่มิติทีละคู่ (หรือ interpolate ระหว่างมุมมอง) แทนที่จะกางดูทุกคู่พร้อมกันในตารางใหญ่ (Daniel Asimov, 1985)
