วิธีรูปแบบข้อดี
Edge Listรายการคู่ (A, B) ที่เชื่อมกันเขียน/อ่านง่าย เปลี่ยนแปลงได้ (add/remove เร็ว)

ทางเลือกแทน Node-Link เมื่อกราฟใหญ่เกิน (แก้ปัญหา "Hairball")

  • Arc Diagram — node เรียงเป็นเส้นตรง 1 แถว, link โค้งเป็นส่วนโค้งเหนือ/ใต้เส้น
  • Chord Diagram — node เรียงรอบวงกลม, link เป็นเส้นโค้งตัดผ่านวงกลม
  • Adjacency Matrix / Heatmap — วาดเป็นตาราง ใช้ matrix reordering (หลักการเดียวกับ Bertin's reorderable matrices ใน Lecture 5) เผย cluster ที่มองไม่เห็นใน node-link

เทคนิคสำหรับ Hierarchical Data

เทคนิคหลักการ
Reingold–Tilford Layoutต้นไม้แนวตั้งมาตรฐาน แต่ละ level = 1 แถว
Radial Treeรากอยู่กลาง กิ่งกางออกเป็นวงกลม
Cone Treeต้นไม้ 3 มิติ หมุนดูได้ (Mackinlay et al. 1991)
Icicle Plotแท่งซ้อนกันตาม hierarchy ความกว้าง = สัดส่วน/จำนวน
Sunburst ChartIcicle Plot ที่โค้งเป็นวงแหวนซ้อนกัน ความกว้างมุม = สัดส่วน (พื้นที่ยังถูกต้องตามลำดับชั้น)
TreemapVisual Variable = Containment (สี่เหลี่ยมซ้อนในสี่เหลี่ยม) พื้นที่ = ค่าข้อมูล
Mosaic Plot / Marimekkoสี่เหลี่ยมแบ่งทั้งกว้างและสูงตามสัดส่วน 2 มิติพร้อมกัน
กับดักสำคัญ: Sunburst ≠ Rose Diagram
Sunburst chart เข้ารหัสด้วยมุม/พื้นที่วงแหวนถูกต้องตามสัดส่วนจริง (เหมือน stacked bar chart ที่โค้งเป็นวงกลม) แต่ Rose Diagram / Polar Area Diagram (เช่นของ Florence Nightingale) เข้ารหัสด้วยรัศมีตรง ๆ ทำให้พื้นที่บิดเบือน (พื้นที่ ∝ รัศมี² เหมือนกับดักวงกลม COVID map ใน Lecture 2) — สองอย่างนี้หน้าตาคล้ายกันมากแต่คนละหลักการเข้ารหัส

Curse of Dimensionality: อัตราส่วนปริมาตร Hypersphere/Hypercube

มิติอัตราส่วน
2D~75%
3D~50%
4D~30%
...100D→ 0%

ยิ่งมิติเยอะ ยิ่งข้อมูลกระจายไปอยู่ "มุม" ของพื้นที่มากขึ้น จุดข้อมูลห่างกันหมด clustering ตามระยะทางแบบปกติเริ่มไม่ได้ผล — นี่คือเหตุผลที่ต้องมี embedding/dimensionality reduction (PCA, t-SNE, UMAP, MDS) มาบีบอัดกลับเหลือ 2D ก่อนจะมองเห็น pattern.
